# m03l05-07: Try it yourself

You can express many input cases in one table test and get a useful name for every failure.

Create a table for a status to health function. Include a successful response, a redirect, a server error, and an unknown code. Give each row a descriptive name and run it as a subtest. Store the expected boolean in the row, then compare it inside the subtest. Add one more boundary case without changing the test loop, and notice how the table remains the source of truth.

- Run each row as a named subtest and report the expected result.
